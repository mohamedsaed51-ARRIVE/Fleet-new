# لوحة متابعة Fleet Support — ARRIVE

تطبيق Google Apps Script (Web App): واجهة HTML واحدة (`index.html`) + API بصيغة JSON على نفس رابط الـ `/exec`، والبيانات من شيت **Master Data**.

## هيكل المشروع

| ملف / مجلد | الدور | يُرفع إلى Apps Script؟ |
|---|---|---|
| `Code.gs` | نقطة الدخول `doGet`: بدون `action` يقدّم الصفحة، ومعه `action` يرجّع JSON | نعم |
| `Backend.gs` | قراءة Master Data، الفلاتر، الـ KPIs، التجميعات، المقارنة الشهرية، الكاش | نعم |
| `Config.gs` | **المصدر الوحيد** لأسماء الشيتات وأرقام الأعمدة وتصنيف الحالات وحد المتابعة | نعم |
| `Helpers.gs` | قراءة التواريخ، `pct_`، `normalizeFilterDate_` | نعم |
| `Reports.gs` | تقرير الإدارة PDF من السيرفر | نعم |
| `Assets.gs` | شعار ARRIVE (data URI) | نعم |
| `index.html` | الواجهة الكاملة — **ملف ناتج بناء، لا يُعدَّل يدويًا** | نعم |
| `DesignSystem.html` | الهوية البصرية (CSS/tokens) — مصدر يُدمج داخل `index.html` وقت البناء | لا (غير مطلوب وقت التشغيل) |
| `parts/markup.html`, `parts/app.js` | مصدر `index.html` (الهيكل + المنطق) | لا |
| `tools/build.py` | يبني `index.html` من المصادر (بحماية) | لا |
| `tests/` | الاختبارات | لا |
| `Dashboard.html`, `Scripts.html`, `Styles.html`, `legacy_untouched/` | النسخة القديمة (`google.script.run`) — لا يخدمها `doGet`، محفوظة كما هي | لا |

## البناء (Build)

المصدر الحقيقي: `parts/` + `DesignSystem.html` + شعار `Assets.gs`. الناتج: `index.html`.

```bash
python3 tools/build.py            # يبني index.html
python3 tools/build.py --check    # يتحقق أن index.html مطابق للمصادر (لا يكتب)
python3 tools/build.py --force    # يتجاوز الحماية (يضيّع أي تعديل يدوي في index.html)
```

الحماية: يحفظ `tools/index.html.sha256` (بصمة آخر ناتج). لو `index.html` اتعدّل يدويًا بعد آخر بناء يتوقف البناء ولا يكتب. ويرفض أي ناتج ينقصه علامات أساسية، أو فيه وسوم `<?` زيادة (تكسر Apps Script template)، أو أصغر من الحالي بأكثر من 10%. كل تعديل في الواجهة: عدّل `parts/` أو `DesignSystem.html` ثم `python3 tools/build.py`.

## الاختبارات

```bash
bash tests/run_all.sh        # build --check + صياغة JS + اختبارات الباك إند (37) تحت 4 Timezones — بدون متصفح
bash tests/run_ui_tests.sh   # متصفح (Playwright + chromium): 27 فحص وظيفي + عدم وجود تمرير أفقي عند 390/820/1440
```

- اختبارات الباك إند تشغّل ملفات `.gs` الحقيقية داخل `vm` مع محاكاة لـ SpreadsheetApp/CacheService، وتُحاكي Timezone الـ Script بمتغير `TZ`.
- اختبارات المتصفح تحتاج `pip install playwright` وchromium. اختياريًا ضع `chart.umd.js` (Chart.js 4.4.1) ومجلد `fontawesome-free-6.5.2-web` في `tests/.deps` (أو `TEST_DEPS=<مسار>`) لعرض الرسوم والأيقونات؛ بدونهما تعمل الصفحة بدون رسوم وتبقى فحوص الأرقام والجداول والفلاتر صالحة.
- البيانات في الاختبارات **مولّدة تجريبيًا** وليست بيانات ARRIVE الحقيقية.

## النشر (Deployment)

1. انسخ إلى مشروع Apps Script: `Code.gs`, `Backend.gs`, `Config.gs`, `Helpers.gs`, `Reports.gs`, `Assets.gs`, `index.html`.
2. **Deploy ← Manage deployments ← Edit ← New version** على نفس الـ Deployment (لا تنشئ Deployment جديد حتى لا يتغير الرابط).
3. افتح رابط `/exec` وتأكد أن الصفحة تحمّل وأن «حالة النظام» خضراء.

## الإعدادات والبيانات

- **المصدر:** شيت `Master Data` (14 عمودًا مقروءة) وشيت `Lists` (قوائم الفروع/أنواع المشاكل/الحالات/Accounts). أسماء الأعمدة والأرقام في `Config.gs` ولا تتغير.
- **الموظفة والمندوب:** من Master Data فقط. أعمدة الشهر/السنة/اليوم في الشيت غير مستخدمة، وتُشتق من «التاريخ».
- **فئات الحالة:** `STATUS_BUCKETS` في `Config.gs` (افتراض يحتاج تأكيد الإدارة). حد «يحتاج متابعة» لنسبة الحل: `REPORT.ATTENTION_RESOLUTION_PCT` (عرض فقط).
- **الكاش:** القيم الخام لـ Master Data تُخزَّن في `CacheService` 60 ثانية، مقسّمة على قطع (حد القيمة الواحدة ~100KB). فوق سقف ~1.8 مليون حرف لا يُستخدم الكاش (الطلب يعمل بقراءة واحدة من الشيت). زر «تحديث البيانات» يمسح الكاش.
- **رابط الـ API:** يُحقن تلقائيًا من `ScriptApp.getService().getUrl()`. القيمة `DEFAULT_API_URL` داخل `parts/app.js` للفتح خارج Apps Script فقط، وإعداد ⚙️ في المتصفح له الأولوية.

## فلتر الفترة (dateFrom / dateTo)

يقارن «يوم التقويم» (`dateKey = yyyy-MM-dd` بتوقيت الـ Script) وليس كائنات `Date`. النسخة السابقة كانت تحوّل `'2026-08-01'` إلى منتصف الليل UTC فتُسقط سجلات أول أو آخر يوم حسب الـ Timezone. السجل بلا تاريخ صالح يُستبعد مع أي فلتر تاريخ كما كان. قيمة فلتر غير صالحة تُرجع `{ ok:false, error }` بدل نتيجة فاضية صامتة.

## حدود وملاحظات معروفة (قرارات إدارية لم تُغيَّر)

1. **الإجمالي ≠ مجموع الفئات الثلاث** عندما توجد حالات غير مصنفة (UNKNOWN): تدخل في الإجمالي وفي مقام نسبة الحل ولا تدخل في أي فئة. الواجهة تعرض تنبيهًا بعددها.
2. **`changePct` في المقارنة الشهرية** = التغيّر **النسبي** في نسبة الحل (وليس فرق نقاط مئوية). تعريف يحتاج قرارًا.
3. **عدد السجلات بتاريخ غير صالح** (`invalidDateRowCount`) على الشيت كله وليس بعد الفلاتر.
4. **التواريخ النصية** (لو وُجدت خلايا تاريخ مخزنة كنص مثل `4/8/2026`) تُقرأ بمحلل JavaScript الأصلي (شهر/يوم). لم يُتحقق من بيانات حقيقية؛ لو الشيت فيه نصوص بصيغة يوم/شهر راجعها.
5. **الأمان:** الـ API عام (النشر «Anyone» ومفيش تحقق). أي شخص معه الرابط يقرأ كل الشحنات والأسماء. إعداد الوصول هو إعداد Deployment وليس في الكود، ولا يوجد `appsscript.json` في الباكيج، فلم يُتحقق منه. تقييده (Anyone with Google account / داخل الدومين) أو إضافة token يغيّر طريقة الدخول، فلم يُطبَّق. `XFrameOptionsMode.ALLOWALL` يسمح بتضمين الصفحة في أي iframe.
6. **PDF السيرفر** (`getAs('application/pdf')`) لم يُجرَّب خارج Apps Script. النسخة عالية الدقة: صفحة التقارير ← طباعة.
7. حد 50% للمتابعة مكرر في `Config.gs` و`parts/app.js` (`ATTENTION_PCT`) — غيّر الاثنين معًا.
8. الملاحظات والتوصيات في التقرير مستخرجة من الأرقام فقط؛ الخطورة والمسؤول والاستحقاق «غير محدد بالمصدر» لعدم وجود أعمدة لها في Master Data.
